# LoveShops

Продвинутая система торговли с NPC-торговцами (Скупщик, Продавец, Аукционист, Банкир).

## Общая структура

LoveShops предоставляет торговцев-NPC:

- **Скупщик (Buyer)** — выкупает предметы у игроков по ценам из конфигурации. Цена зависит от репутации.
- **Продавец-барахолка (Seller)** — по расписанию продаёт предметы, выкупленные скупщиком.
- **Аукционист (Auctioneer)** — аукционы редких предметов с anti-snipe.
- **Банкир (Banker)** — обмен физических монет LoveCore: укрупнение мелочи или размен крупных номиналов.
- **Военный торговец (WarMerchant)** / **Странник (Wanderer)** — отдельные роли.

Все используют валюту LoveCore (`LoveEconomy`) — физические монеты в инвентаре.

## Банкир

ПКМ по NPC типа `banker` открывает GUI:
- **Укрупнить** — весь баланс списывается и выдаётся крупными номиналами
- **Разменять** — одна монета выбранного номинала → более мелкие

Создание:
```
/npc create banker Банкир
/loveshopsadmin npc create banker
```

Комиссия: `banker.fee-percent` в `config.yml` (по умолчанию 0).

## Команды

| Команда | Описание |
|---|---|
| `/loveshopsadmin npc create <type>` | type: buyer, seller, auctioneer, warmerchant, wanderer, **banker** |
| `/loveshopsadmin npc delete` | отвязать NPC |
| `/loveshopsadmin reload` | перезагрузка конфига |

## Зависимости

- **LoveCore** (обязательно) — LoveEconomy
- **Paper 1.21**
- **Citizens** или **LoveEssential** (мягкая; выбирается в `integrations.npc-provider`: `global` по умолчанию - как решено в `integrations.provider` LoveCore, или явно `citizens` / `loveessential`) — NPC через контракт `NpcProvider` из LoveCore

## Поздний запуск NPC-провайдера

NPC-провайдер выбирается через LoveCore и проверяется повторно при каждом обращении.
Первые 200 тиков после включения отведены на асинхронную загрузку провайдеров: временное
отсутствие в этот период не печатается как ошибка. В конце ожидания выполняется проверка;
реальное отсутствие или потеря уже работавшего провайдера по-прежнему диагностируется.
После появления LoveEssential интеграция восстанавливается без перезапуска потребителя.
Видимый номер LoveEssential разрешается в постоянный ключ NPC; новые привязки сохраняют
ключ, выданный провайдером. Число само по себе не означает, что выбран Citizens.

Если существующий NPC действительно удалён, запись роли удалять не нужно:
`/loveshopsadmin npc rebind <номер записи LoveShops> [номер или ключ NPC]`.
Без последнего аргумента игрок смотрит на NPC назначения. Сохраняются ID и UUID записи,
тип, название и связанные данные банка/магазина; местоположение берётся у выбранного NPC.
Обновление SQLite проверяет прежнюю привязку и время изменения. Старый NPC не уничтожается;
чужую роль, лавку, стража или феодала присвоить нельзя. Настройки событий перепривязкой
не заменяются. Пример: запись банкира №7 — это первый номер в сообщении, а не номер NPC.

Старая числовая привязка LoveEssential без подтверждающего тега UUID не присваивается
новому NPC автоматически: видимые номера могут использоваться повторно. Для такой
записи администратор явно выбирает NPC командой `rebind`; сохраняется постоянный ключ.
