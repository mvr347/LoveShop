# Торговые точки: план и честный статус

Обновлено 2026-10-02. Раньше эта таблица отмечала ✅ то, чего в коде не было (команды `/tp` и
`/tradepointadmin` не были подключены, меню «Торговля» нигде не открывалось). Ниже — что есть на самом деле.

## Сделано (PR «GUI по gui_gen»)

| Что | Где |
|---|---|
| Главное меню: **Торговля / Склад / Управление** в Header (слоты по `MarketLayout.controlSlots`), карточки состояния в рабочей зоне | `StallOwnerGui` |
| Торговля: Продажа, Скупка, Касса; скупка выключена в режиме «Только продажа» | `StallTradeMenuGui` |
| Управление: режим торговли (по умолчанию «Только продажа»), улучшение, передача, открыта/закрыта; скидки, ЧС, стража | `StallManageGui` |
| Перетаскивание предмета мышью и Shift-клик из инвентаря: витрина, скупка (образец), склад | `MarketGuiListener`, `MarketGui.acceptCursor` |
| Установка цены как в LoveDuels: Shift — номинал, ЛКМ +, ПКМ −, «Подтвердить» неактивна без цены, «Закрыть» в последнем слоте, предмет возвращается при Esc | `PriceGui`, `PriceInput` |
| Пагинация в 54-слотовых меню только на слотах 36 / 44 | `MarketGui.pager` |
| Все тексты меню в `lang.yml` (`market.gui-*`), тест на наличие ключей | `LangKeysTest` |
| Напоминания об аренде по ступеням + слова о конфискации | `RentReminderMath`, `TradePointManager.remindRent` |
| Серый «закрыто» знак убирается вместе с удалённой точкой | `StallNpcService.removeClosedSign` |

## Сделано (PR «команды, мастер, Феодал»)

| Что | Где |
|---|---|
| `/tradepoint` без аргументов открывает меню владельца; тексты команд в `lang.yml` | `TradePointCommand` |
| `/tp` · `/тп`: к своей точке; `/tp <id>` — к любой (право `loveshops.tp.any`); всё остальное передаётся ванильному `/tp` | `TradePointTeleportCommand` |
| `/tradepointadmin` (`tpadmin`, `tpa`): `npc create/remove/tp taxer\|seller\|stall`, `create`, `wizard`, `delete <id> confirm`, `owner set/remove`, `lvl set/add/remove`, `price`, `list`, `info`, `reconcile` | `TradePointAdminCommand` |
| Мастер создания: углы зоны → торговец → табличка «закрыто» → табличка с id → точка телепорта → создать/отмена; кнопки в чате, частицы-превью | `PointWizard` (чистая логика, тесты), `WizardService` |
| Табличка с id в каждой точке (id и «свободна»/ник арендатора, обновляется само) | `StallNpcService.updateIdSign` |
| NPC «Феодал» (`seller`): список точек, аренда на 1–N недель, продление, возврат точки с возвратом % остатка, найм стражи | `feudal/*`, `RefundMath` |
| LoveClaimsAPI: создание/удаление/аренда точек, сборщик налогов по имени | `ClaimsLink`, `ClaimsBridge` |

Идентификатор точки — её имя в LoveClaims (его задаёт админ в `create <id>`).

## Известные риски

- Всё проверено только компиляцией и юнит-тестами, на живом сервере не запускалось.
- Нужна версия LoveClaims с новыми методами `LoveClaimsAPI` (создание/аренда точек); со старой аренда у Феодала и мастер не заработают.
- Стража нанимается только у Феодала; в «Управлении» остался информационный блок со статусом.
